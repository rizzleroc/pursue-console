# Pursue Console — UI / Data Review (2026-06-01)

Full-stack audit of `rizzleroc/pursue-console`. Driven by 4 parallel
subagent investigations + a deployed-site verification pass via
whipgen's real browser. Findings ordered by signal-to-effort, not
by topic — fix the top items first.

---

## The 10 things to fix or surface, ranked

### 1. **`DOSSIER` is in the main nav but unreachable on its own**
`src/components/Header.jsx:23` puts DOSSIER in the PRIMARY tab row, but
clicking it lands on `DossierView.jsx:72-77`'s "no record selected"
empty state. The view only renders meaningfully when reached via
`onSelect(event)` from another view. Either drop it from the nav, or
have it auto-load the most recently-viewed event (we already have
`window.__EVENTS_BY_ID` and selection state at `App.jsx:48-73`).

### 2. **SEARCH and SEMANTIC look like duplicates from the nav**
Two adjacent tabs, two full-text query interfaces, no UI hint when to
use which. SEARCH is a MiniSearch lexical index over 276 docs;
SEMANTIC is a 25 MB transformers.js + 5,665-chunk dense-vector index.
Two reasonable moves:
- Merge into one **SEARCH** tab with a lexical-or-semantic toggle and
  a one-line explainer of each.
- Keep both, but add a small "WHY TWO?" affordance + clear differentiator
  ("EXACT MATCH" vs "MEANING MATCH").

### 3. **199 mined entities + 67 mined dates are computed but rendered nowhere**
`scripts/build-patterns.mjs` writes `public/patterns.json` with five
buckets — shape (6), behavior (6), sensor (4), **entity (199), date (67)**.
NetworkView only consumes shape/behavior/sensor; the 266-row entity-and-
date table is unused. Two low-effort surfaces:
- An **ENTITIES** strip in DossierView right below the existing
  signatures section (`DossierView.jsx:168-187`) — pull the entities
  this event references, link each to a corpus-wide "who else mentions
  USCENTCOM" filter.
- A small **DATE SCATTER** rail in TimelineView or AtlasView, plotting
  mined dates against catalogued event dates so we can see archive-claim
  density on the real timeline.

### 4. **Only 1 of 121 events has `coverage.status === "complete"`**
From `public/coverage.json`:
```
gap:      63   (52%)
no-data:  56   (46%)
complete:  1   (1%)
mismatch:  1   (1%)
```
This is the loudest signal in the corpus and it's invisible in the UI.
Two surfaces:
- A **coverage heatmap** in the LIVE dashboard's "DOCUMENT PROGRESS"
  rail (it currently shows READY/IMPROVING/QUEUED/MISSING but uses a
  different denominator — corpus-stats.json says "65 of 244" ready,
  while coverage.json says only 1 is complete; the two definitions
  are not reconciled in either UI or docs).
- An **"events needing review"** sort/filter in ReviewView keyed off
  `coverage.status === 'gap' || 'mismatch'`, ordered by chars × gap%.

### 5. **Release 02 is 7/64 catalogued and the UI doesn't flag it**
`corpus-stats.json` shows R2 at 11% catalogued vs R1 at 75%. The header
band reads `R1 128/162 · R2 92/64 records` which is technically accurate
but reads as "R2 is at 144%" — confusing because the 92 is _pages_ and
64 is _inventory total_, not catalogued. Change to `R1 121/162 ·
R2 7/64` and the gap becomes visible at a glance.

### 6. **DossierView shows 6 of 10 computed semantic neighbors**
`public/event-similarity.json` stores top-10 nearest neighbors per
event with cosine ≥0.30. DossierView renders 6 (line 439-468). Either
render 10 or, better, render 6 + a "show more" affordance. Cheap win.

### 7. **75 of 220 events are in the semantic index — the other 145 are dark**
`event-similarity.json` covers 75 events. The other 145 catalogued
events (mostly auto-imported or text-poor) have **no semantic
neighbors at all**, so they never surface in Network/Dossier
similarity views. Either:
- Lower the chunk-quality threshold in `scripts/build-event-similarity.mjs`
  (currently 0.25 mean quality) to bring in OCR-only events.
- Mark them clearly in NetworkView with an "EMBEDDING N/A" pill so
  users don't assume "no neighbors" means "no semantic siblings."

### 8. **Mobile nav is broken — 11 tabs scroll horizontally with zero affordance**
`Header.jsx:92` uses `overflow-x-auto no-scrollbar`. On small screens
tabs beyond `MEDIA` are off-screen with no visual hint they exist.
Add a right-edge gradient + a chevron, or rebreak into a hamburger /
"more" overflow at `<sm` breakpoint.

### 9. **SearchView has no "no results" state**
`SearchView.jsx:85-96` returns `null` when results are empty. Type
nonsense → blank page → user thinks the app is broken. Symmetric fix:
TimelineView silently hides empty eras at `TimelineView.jsx` — should
show "no events in 1980s" rather than dropping the section.

### 10. **Two-header pattern + filter shadowing**
Header (brand + nav) + `RecordFilterBar` (search + dropdowns) read as
two separate UI zones at the top of every catalogue view. Worse:
SearchView has its own `agencyFilter` / `eraFilter` local state
(`SearchView.jsx:72-73`) that overrides the header-level filters
without telling the user. Pick one filter authority and propagate.

## What the data tells us (corpus-level insights, none currently surfaced)

These are findings from running the build outputs through `node -e`
inspection. None of them are in the UI today.

### **"Light" dominates the corpus.**
The shape term `light` has 5,519 mentions across 42 events — most
concentrated in the FBI 62-HQ-83894 sections (4,534 alone). The
archive is heavily skewed toward 1940s–50s sighting prose, not modern
sensor encounters. A view that surfaces _term density per event_
would make this immediately legible.

### **Two semantically-distinct clusters dominate the index.**
By skimming `event-similarity.json`:
- **FBI 62-HQ-83894 cluster** — 11 internal-section neighbors with
  cosine 0.94–0.98. Tight intra-document clustering, this is one
  case file masquerading as 11 events.
- **Modern Middle East / USCENTCOM cluster** — 18 events anchored by
  USCENTCOM (202 mentions / 18 docs), tightly internally clustered,
  weakly connected to anything else.
Neither cluster is named or highlighted in the UI. NetworkView would
benefit from a "named clusters" overlay (k-means on event vectors,
labeled by top distinctive term).

### **Geography is underrepresented in ways that matter.**
By region: NA 80, ME 77, Space 18, EU 14, Unknown 12, AP 10, Asia 4,
**Africa 4, Oceania 1**. The UI lets you filter by region in the
header, but there's no surface that says "Africa and Oceania are
near-empty — these are likely archive gaps, not data gaps."

### **OCR quality is a content-classification signal we ignore.**
Embeddings-info.json shows mean-quality 0.554 for vision-OCR chunks,
0.48 for raw OCR, 1.0 for curated. Coverage.json tracks per-event
human/vision/OCR split. Nothing in the UI exposes "this dossier's
content is 80% machine OCR — treat the prose accordingly." Especially
relevant for `dispute_kind = page-intrinsic` pages that need human
typing.

### **`handwritten` is a 1,649-mention pattern across 16 events.**
This is a metadata pattern — pages with handwritten margin notes that
OCR mis-handles. It's effectively a "scanned-document indicator"
across the corpus. Worth surfacing as a tile-corner badge in
MediaView, and as a filter ("show only events with handwritten
annotation").

## Architecture findings (from code-audit subagent)

### Risks worth fixing now

1. **`LiveFeedView.jsx` (885 lines)** and **`SemanticSearchView.jsx`
   (867 lines)** are monolithic. Both pack 7+ `useState` calls and
   4-7 `useEffect` chains. Split sub-components into their own files;
   the LiveFeedView dashboard widgets (UtcClock, IngestHistogram,
   Oscilloscope, BearingDial, SignalTable, BandColumn, AgencyGauge)
   are obvious extraction targets.
2. **Module-level promise caches** in DossierView (`_extractsP`,
   `_simP`), NetworkView (`_simP`, `_patP`), SemanticSearchView
   (`_vectorsP`, `_modelP`). They never invalidate; mid-session data
   updates won't reach the UI. Wrap with a `useRef`-cached fetcher
   that has an explicit "refresh" entry point.
3. **No error boundary.** A cascading fetch failure in
   SemanticSearchView (25 MB model, slow CDN) leaves the UI in
   half-loaded state. Wrap each `Suspense` boundary in an
   `ErrorBoundary` that explains what failed.

### Strengths to preserve
- All 12 views are active and cross-linked. No dead code in
  `src/views/` or `src/components/`.
- Lazy-loaded `AskView` + `SemanticSearchView` keep first paint fast.
- i18n is wired everywhere (audit pending, see below).
- Cross-view navigation via `onSelect(event)` is consistent and
  testable.

## UX friction (from flow-audit subagent)

Punch list, terse:

- **First paint is brand-first.** LaunchOverlay is 100% promotional;
  no onboarding for the actual console. LIVE view has no empty
  state — if live-feed.json fails, dashboard renders empty without
  any "no signal" indicator.
- **Filter widgets are inconsistent.** Header uses `<select>`,
  MediaView uses pill toggles, SearchView has hidden dropdowns.
  Pick one pattern.
- **Modal dismiss is inconsistent.** LaunchOverlay handles Escape;
  MediaView modal, VolunteerModal, ReviewView combine modal don't.
- **Filter scoping isn't visible.** CATALOGUE_VIEWS at `App.jsx:117`
  controls which views show the header-filter "X of Y" — but the
  set is implicit; users can't see why MEDIA shows a count and LIVE
  doesn't.
- **No focus indicators.** Tabs are real `<button>`s but no visible
  focus ring. Keyboard navigation works but is invisible.
- **Color contrast borderline.** `emerald-700`/`emerald-800` text
  on `#020806` background may fail WCAG AA. Worth testing with
  axe-core in a dev pass.

## i18n audit

i18n is in good shape — the headline number is **98.4% key coverage
across 18 locales**. Same 5–6 keys missing across most non-EN locales,
all of them recent additions to the freshness rail (e.g.
`freshness.pages_indexed`, `freshness.volunteer_pages`,
`freshness.by_source`).

### Coverage
- **18 locales** under `src/i18n/locales/` — EN canonical with 551
  keys across 19 sections.
- **16 LTR + 2 RTL** (Arabic, Hebrew) — RTL handled at the document
  root via `setAttribute("dir", lang.dir)` in `src/i18n/index.jsx:84`.
  No hard-coded `dir=` attributes in JSX; Tailwind `[dir="rtl"]`
  selectors handle layout flipping.
- Spot-check ES / JA / AR: all properly translated, not machine
  output. Native-language section headers (`RESUMEN`, `概要`,
  `الملخص`), proper honorifics, domain-aware Arabic translation of
  technical terms.

### Hard-coded strings to clean up (10 worst)
All in error/diagnostic paths — low user-facing impact, easy to wrap:
1. `SemanticSearchView.jsx:230` — `"Failed to load embeddings: {error}"`
2. `SemanticSearchView.jsx:250` — `"Vectors not yet loaded"`
3. `SemanticSearchView.jsx:368` — `"Drop PDF or .txt files only."`
4. `SemanticSearchView.jsx:372` — `"Model load failed before ingest: {error}"`
5. `LiveFeedView.jsx:279` — `"HTTP fetching live-feed"`
6. `ReviewView.jsx:103` — `"COPIED ✓"` / `"COPY MERGED TEXT"`
7. `ReviewView.jsx:111` — `"COPY RESOLVE CMD"`
8. `SourceMix.jsx:15-55` — static source labels (HUMAN, GPT-VISION,
   GEMINI, CLAUDE, OCR, PDFJS)
9. `SourceMix.jsx:70-73` — confidence badges (HIGH, MED, LOW, ONE-OFF)
10. `Primitives.jsx:63` — `"DEPT/"` abbreviation

i18n is **not** a top-10 fix item; the corpus-coverage and
nav-confusion issues at the top of this doc are bigger UX wins. But
patching the 5–6 missing `freshness.*` keys and wrapping the
10 hard-codes is a half-day task someone can pick up.
